Creator Analytics — Project Handoff Summary
Project goal
Build an end-to-end creator analytics and scheduling system for gaming short-form content that:
Syncs Buffer posts and analytics automatically
Stores everything in Supabase
Labels clips by content characteristics
Learns which posting slots work best for different types of clips
Maintains a target cadence of 14 TikToks + 14 YouTube Shorts per week
Keeps long-form YouTube separate/manual
Requires manual approval before changing live Buffer schedules
Eventually becomes a standalone Creator Analytics web app instead of relying heavily on Google Sheets/Make
Primary content includes gaming funny moments, squad banter, reactions, gameplay moments, etc. across games such as Halo, Minecraft/RLCraft, Rainbow Six Siege, Ready or Not, and others.

Content-aware scheduling
The scheduler does not simply choose a generic “best time.”
It uses available historical performance and content labels to choose a posting slot.
General intended hierarchy:
Specific content match
→ partial label match
→ game/type-level performance
→ broader platform posting-time performance
This prevents small samples from being overfit.

Duplicate proposal bug and migration 028
A significant bug was discovered after the first successful content-aware batch.
Previously applied Buffer posts were being given new Pending Proposal IDs during a later proposal refresh.
The actual Buffer application duplicate protection worked, but the proposal generator was reconsidering completed posts.
Root cause:
Migration 026 created content-aware proposals without correctly locking the corresponding post with:
schedule_evaluated_at
Migration 027 later relied on that field when deciding whether a post was eligible.
Once an original proposal became Applied, it was no longer considered an active proposal, so the same Buffer Post ID could be reconsidered.
Migration added
028_prevent_duplicate_content_aware_proposals_v2.sql
The migration:
Backfilled schedule_evaluated_at for posts with proposal history
Rejected accidental duplicate Pending proposals while preserving database audit history
Hardened the manual content-aware proposal creation function
Hardened the automatic refresh function
Added proposal-history protection in addition to the evaluation lock
Did not edit Buffer

Core development principle
Do not replace a working component until the replacement is tested against the known-good system.
The current Buffer + Make + Supabase pipeline should act as the reference implementation while the app is being built.
